## The API, as it was

Base URL was tenant-templated: https://{instance}.blameless.io/api/v1
Two path shapes existed.

- Attested in Blameless' own published client code (fetched from github.com/blamelesshq,
  2026-08-29): /api/v1/incident-severities, /api/v1/identity/tenant,
  /api/v1/identity/user/authName/{name}, /api/v1/prometheus/settings, and the RPC form
  POST /api/v1/services/{Service}/{Method} with services SLOServiceCrud and
  SLOTimeSeriesServiceCrud.
- Documented on the removed reference and recoverable only from search-engine memory of
  docs.blameless.com/api/api-reference/* (the host itself returns nothing):
  /api/v1/incidents, /api/v1/incidents/{incidentId},
  /api/v1/incidents/{incidentId}/events. Treat these as low-confidence — they could not be
  verified against a live page.

Authentication: Auth0 machine-to-machine client credentials
(https://blamelesshq.auth0.com/oauth/token, grant_type client_credentials, audience set to
the tenant host), presented to the API as an Authorization: Bearer header. The Terraform
provider used an instance URL plus an API key (BLAMELESS_INSTANCE / BLAMELESS_KEY).
Credentials were not self-service — Customer Success issued them.
Authorization was rule-based (named rules such as IncidentRead); that rule catalogue was
published only on docs.blameless.com and is not recoverable.

## SLO specification dialect

The Blameless SLO CLI consumes OpenSLO-shaped YAML — kinds Service, SLI, SLO, UserJourney
and ErrorBudgetPolicy, with ratioMetric (good/total) and thresholdMetric (op/value) — but
every published spec file declares `apiVersion: blameless/v1alpha` rather than an OpenSLO
apiVersion. The files are therefore not portable to OpenSLO-conformant tooling.
